# 📘 项目 V4 重构执行规范（AI 执行版）

---

## 0️⃣ 项目背景

当前项目状态：

* 功能已完整
* 页面已较多
* 缺乏产品结构壳层
* 缺乏统一设计系统
* 缺乏状态体系
* 目录为页面驱动结构

V4 目标：

> 从“功能集合型系统”升级为“完整产品结构型系统”。

---

# 1️⃣ 总体执行原则

AI 必须遵守以下规则：

1. 不删除现有业务逻辑
2. 不修改现有 API 数据结构
3. 优先做结构抽象，不改功能
4. 每阶段必须通过验收后再进入下一阶段
5. 所有新增内容必须模块化
6. 禁止增加新的一级导航项

---

# 2️⃣ 重构阶段划分

---

# 阶段一：产品壳层构建（AppShell）

## 🎯 目标

建立统一 Layout 系统。

---

## 📁 新增目录结构

```
src/layouts/
├── AppShell.vue
├── DesktopLayout.vue
├── MobileLayout.vue
├── components/
│   ├── AppHeader.vue
│   ├── AppSidebar.vue
│   ├── AppTabbar.vue
│   └── AppContainer.vue
```

---

## 🔧 实施步骤

1. 创建 AppShell 组件
2. 所有路由页面必须被 AppShell 包裹
3. 桌面端使用 Sidebar
4. 移动端使用 Tabbar
5. Header 全局固定

---

## ✅ 验收标准

* 所有页面不再直接渲染在 router-view 根层
* Layout 可响应式切换
* 页面不包含导航代码
* 一级导航 ≤ 5

---

# 阶段二：Dashboard 首页重构

## 🎯 目标

建立真正产品首页。

---

## 📁 新增模块

```
src/modules/dashboard/
├── pages/
│   └── DashboardPage.vue
├── components/
├── store/
```

---

## 📌 首页必须包含：

* 今日提醒模块
* 猫咪概览卡片
* 最近记录列表
* 快捷操作区
* 小型趋势图

---

## ❌ 禁止

* 不允许把已有页面简单拼接
* 不允许直接复用完整页面作为首页模块

---

## ✅ 验收标准

* 打开系统默认进入 Dashboard
* Dashboard 不超过 5 个模块区块
* 所有区块为卡片式结构

---

# 阶段三：设计系统抽象

## 🎯 目标

建立 Design Token 系统。

---

## 📁 新增目录

```
src/styles/
├── tokens.css
├── spacing.css
├── radius.css
├── shadow.css
```

---

## 必须抽象变量：

* 主色
* 辅助色
* 圆角
* 间距
* 阴影
* 字体层级

---

## 规则

* 禁止组件中写死颜色
* 禁止组件写死 px 间距
* 必须全部使用变量

---

## ✅ 验收标准

* 全项目无裸露 #hex 颜色（除变量定义处）
* 所有 padding/margin 使用变量

---

# 阶段四：状态系统构建

## 🎯 目标

统一 Loading / Empty / Error。

---

## 📁 新增

```
src/components/system/
├── LoadingState.vue
├── EmptyState.vue
├── ErrorState.vue
├── Skeleton.vue
```

---

## 规则

* 页面不得自行实现 loading
* 必须使用统一状态组件
* 状态组件支持 slot

---

## ✅ 验收标准

* 删除页面内自定义 loading
* 状态 UI 风格统一

---

# 阶段五：模块结构重构

## 🎯 目标

从页面驱动改为领域驱动。

---

## 📁 目标结构

```
src/modules/
├── cat/
├── record/
├── compare/
├── dashboard/
├── auth/
```

每个模块必须包含：

```
api/
components/
pages/
store/
types/
```

---

## 规则

* 页面只能访问本模块 API
* 禁止跨模块直接调用
* 公共组件放入 shared 目录

---

## ✅ 验收标准

* 页面目录不再散乱
* 模块边界清晰
* API 分类明确

---

# 阶段六：移动优先优化

## 🎯 目标

实现 App 化体验。

---

## 规则

* 最大宽度 1200px（桌面）
* 移动端最大宽度 430px
* 页面统一使用 container
* 卡片纵向堆叠

---

## 验收标准

* 所有页面移动端无横向滚动
* Tabbar 固定底部
* 触控按钮高度 ≥ 44px

---

# 3️⃣ 统一回归测试清单

每阶段完成后，必须验证：

* 所有旧功能正常
* API 请求无变化
* 无新增控制台报错
* 无死链接路由
* 无样式错乱

---

# 4️⃣ 版本完成定义（Definition of Done）

当满足以下条件时，视为 V4 完成：

* 有统一 AppShell
* 有产品首页
* 有统一设计变量
* 有统一状态组件
* 有模块化结构
* 移动端体验达标

---

# 5️⃣ 推荐 AI 执行方式

建议使用如下循环执行策略：

1. 只给 AI 当前阶段任务
2. 让 AI 输出修改文件清单
3. 让 AI 先输出 diff 方案
4. 再让 AI 生成最终代码
5. 每阶段单独提交 commit

---

# 6️⃣ 不允许做的事

* 不允许大面积重命名现有文件
* 不允许修改数据库结构
* 不允许同时重构多个阶段
* 不允许增加新业务功能
