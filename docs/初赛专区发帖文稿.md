## 1. Demo 简介

**是什么**：一款 Web 端智能猫咪健康管理系统，采用响应式页面设计，可在桌面浏览器和手机浏览器中访问，也支持 PWA 形式添加到主屏。

**面向谁**：

- 第一次养猫、不知道喂多少、何时打疫苗的新手铲屎官；
- 家有多只猫、需要分别记录体重、健康、疫苗的多猫家庭；
- 想随时问“它最近胖了没”“疫苗到期了吗”却不想翻表格的养猫用户。

**Web 端移动登录页展示**：

![哈吉咪养成计划 Web 端移动登录页](images/panghu-mobile-home.png)

*Web 端移动登录页：用户通过手机浏览器访问 Demo 后，可选择立即登录或注册账号，登录后进入猫咪成长记录、喵喵医生和养猫指南等核心功能。*

**主要功能**：

1. **喵喵医生 AI Agent：一个统一的猫咪管理入口**：用户不用记住每个功能在哪里，只要直接对喵喵医生说“帮奶糖记一笔体重”“登记一下疫苗”“记录今天的成长状态”“看看它最近健康怎么样”，Agent 就能理解意图，并自动调用成长记录、疫苗登记、体重记录、健康评估、知识检索等功能。
2. **从“找功能”变成“说需求”**：传统养宠工具需要用户自己进入不同页面：体重在体重页，疫苗在疫苗页，成长记录在时间线里。这个 Demo 把这些能力都接入 Agent，用户可以像聊天一样完成操作，Agent 会帮你判断该用哪个工具、需要哪些信息，并引导补全缺失内容。
3. **数据驱动的个性化建议**：喵喵医生不会泛泛回答，而是会读取猫咪档案、成长记录、体重历史、疫苗状态和养护知识库，再生成健康评估、异常提醒、陪玩推荐或后续照护建议。每次回答都尽量基于“我家这只猫”的真实数据。
4. **可视化执行过程，证明 AI 真的在做事**：Agent 的执行过程会在前端展示为任务卡片、状态标签和结构化结果，比如正在读取档案、调用体重记录、生成健康评估、推荐陪玩游戏等。用户能看到 AI 不是凭空生成答案，而是在一步步调用能力完成任务。

## 2. Demo 创作思路

**灵感来源**：

养猫过程中，很多问题并不是“有没有知识”，而是“知识能不能结合我家这只猫”。比如同样是体重问题，幼猫、成猫、英短、田园猫、多猫家庭的判断标准都不一样。传统笔记类工具只能记录，通用 AI 又不了解具体猫咪档案，所以我想做一个真正围绕“自家猫数据”工作的 AI 养猫顾问。

**想解决的问题**：

- 新手铲屎官不知道猫咪体重、疫苗、饮食是否正常；
- 多猫家庭很难同时管理多只猫的成长记录和健康信息；
- 通用 AI 给出的养护建议太泛，不能结合具体猫咪档案；
- 用户需要一个既能记录数据，又能基于数据主动解释和建议的系统。

**为什么做这个方向**：

我判断宠物健康管理不应该只是“表单记录”，而应该变成“数据 + AI 顾问”的组合。Demo 阶段没有选择原生 App 或小程序，而是选择 Web 端，是因为 Web 更适合快速迭代、跨平台访问，也方便评审直接打开链接体验。技术上选择 LLM Agent + Tool Calling，是为了让 AI 不只是回答问题，而是能真正调用猫咪档案、体重记录、疫苗记录、知识检索等工具完成任务。

喵喵医生是 Demo 的核心亮点。它不是单纯调用一次大模型，而是采用 Agent 流程：

## 6. 开发心得

这次 Demo 最大的收获是：TRAE 更适合扮演“工程协作者”，而不是单纯的代码补全工具。

我在开发中形成了几个经验：

- **先规划再实现**：复杂功能先让 TRAE 拆解方案，再进入代码实现，能减少返工；
- **把 AI 能力产品化**：喵喵医生不是简单聊天，而是结合猫咪档案、健康数据和知识库进行回答；
- **让执行过程可见**：用户能看到 AI 读取了哪些数据、参考了哪些知识，这会增强信任感；
- **Web 端优先更适合 Demo**：无需安装 App，评审打开链接即可体验，也方便后续扩展为 PWA；
- **测试很重要**：让 TRAE 同步补测试，可以避免功能越来越多后出现回归问题。
