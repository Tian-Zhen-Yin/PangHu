一、技术演进时间轴

意图分类近 10 年经历了 规则 → 浅层 ML → 深度学习 → 预训练 → 大模型 五次范式跃迁。下图标出每一代的代表技术与本项目的位置。

2014~2017 · 规则 / 词典 + SVM / LR
字符串匹配 + 浅层分类器。⚠️ 你当前实现处于这一代
2018~2020 · RNN / BiLSTM + Word2Vec
深度学习初代,引入 Embedding,但仍需大量标注
2019~2022 · BERT 微调 + Rasa DIET
预训练模型主导,准确率突破 90%+,工业广泛部署
2022~2023 · Sentence Embedding 语义召回
OpenAI / BGE embedding 普及,余弦相似度成为可靠置信度指标
2023~now · LLM Few-shot / Function Calling
意图分类被工具调用吸收,GPT-4 / Claude / GLM-4 原生支持
2024~now · Hybrid Routing 多策略融合 ⭐ SOTA
规则 fast-path + Embedding 召回 + LLM 兜底,工业当前最佳实践

三、八大方案详解

① 规则 / 关键词匹配 (Rule-based)

代表实现:Rasa KeywordIntentClassifier、Aho-Corasick、Trie 树

维度评估
准确率(已知模式)极高
准确率(自然语言)低
延迟<1ms
维护成本词表越大越脆弱
可解释性命中哪个词一目了然
📌 Rasa 官方建议:仅用于小型 demo 或作为 fast-path 子组件,生产环境不推荐独立使用。
② 传统机器学习 (SVM / LR / GBDT)

代表实现:Rasa SklearnIntentClassifier、MitieIntentClassifier

特征工程:BoW / TF-IDF / N-gram / 字符级 n-gram(中文友好)

2020 年后被 BERT 时代替代,但仍在低算力嵌入式场景有应用。

③ Rasa DIET (Dual Intent and Entity Transformer)

2020 SOTA 开源方案。同时做意图分类+实体识别,共享 Transformer 编码器,稀疏+稠密双特征融合。

pipeline:
  - name: JiebaTokenizer
  - name: CountVectorsFeaturizer
  - name: DIETClassifier
    epochs: 100

准确率 ~92%,适合 20~200 意图、有标注数据、需要私有化部署的场景。银行、客服大量采用。

④ BERT / RoBERTa 微调

主流大厂方案。BERT(768d CLS) → Dropout → Dense → Softmax。

美团搜索意图模型公开数据显示,引入多任务 fine-tuning 后准确率提升 219bp。

缺点:部署复杂(需 ONNX/Triton),训练数据量大,难以快速迭代。

⑤ Sentence Embedding + ANN 检索 ⭐

2023~2024 工业界主流选择。核心思路:

离线: 每个意图准备 5~20 句 anchor → embed → Faiss/Milvus/pgvector
在线: user_msg → embed → ANN top-K → 投票 + 余弦相似度作为真实置信度
✨ 关键优势:cos_sim ∈ [-1, 1] 是数学严谨的真实置信度,可用统计方法找最优阈值。

新增意图只需加 anchor 句,无需重训。冷启动极佳。

⑥ LLM Zero/Few-shot 分类

用 Prompt 让 LLM 输出 JSON: {"intent": "...", "confidence": 0.9}

⚠️ 业界教训:用 Prompt 硬刚 JSON 输出意图被列为反模式。
1) LLM 自报 confidence 不可靠(系统性偏高 0.9+)
2) JSON 经常格式错误需要重试
3) 100+ 意图时 prompt 爆炸

推荐改用 Constrained Decoding 或 Function Calling(下一方案)。

⑦ LLM Function Calling / Tool Use ⭐⭐⭐

核心范式:把意图分类问题转化为工具选择问题。

tools = [
  { name: "add_growth_record",
    description: "当用户想记录猫咪日常成长、上传照片日记时调用",
    parameters: {...} },
  { name: "add_weight_record",
    description: "当用户提到具体体重数值并想记录时调用",
    parameters: { weight: number, unit: string } }
]
LLM 输出: 调用 add_weight_record({weight: 4.5}) ≡ weight_record 意图

GPT-4o 准确率 96%、Qwen-72B / GLM-4 ~93%。PangHu 项目天然适合此方案(意图与工具一一对应)。

⑧ Hybrid Routing 混合路由 ⭐⭐⭐ 工业 SOTA

核心思想:不同意图用不同方法,分层路由

flowchart TB A[用户消息] --> B{L1: 高特异性词?
妙三多/狂犬/图片附件} B -- 命中 --> R1[直接返回 意图] B -- 未命中 --> C[L2: Embedding 召回
余弦相似度 top-1] C --> D{相似度 >= 0.75} D -- 是 --> R2[返回最相似意图] D -- 否 --> E[L3: LLM Function Calling
语义理解兜底] E --> R3[返回 LLM 选择的工具] style A fill:#FFE5B4,stroke:#F4A261 style R1 fill:#52B788,stroke:#2A9D8F,color:#fff style R2 fill:#52B788,stroke:#2A9D8F,color:#fff style R3 fill:#52B788,stroke:#2A9D8F,color:#fff

实际产线流量分布:L1 ~20% · L2 ~60% · L3 ~20%,平均延迟 ~120ms,准确率 95%+。

四、置信度方案对比(关键章节)

🔥 核心命题:之前讨论已确认,PangHu 当前的"置信度"实际是关键词字符占比,并不是真实概率。基于它做阈值切换的方案(如混合路由 if confidence>0.85)在统计上不成立。
🎯 置信度可靠性 & 可阈值化对比
可比性:同一指标在不同样本间能否互相比较;校准度:数值与真实正确率的拟合程度
📖 图表解读:
• 关键词密度(你当前)在两个维度上得分都最低——这正是之前讨论指出"置信度有问题"的本质。
• Embedding 余弦相似度是数学严谨的指标,可在不同样本间直接比较,且经过 calibration 后可阈值化。
• LLM 自报置信度看似直观,但实际校准度差(模型倾向于报 0.9+ 不论对错),不适合做阈值。
• BERT Softmax 经过 temperature scaling 后是工业上最严谨的概率指标。
• Function Calling 是否触发是二值信号,虽然简单但最干净。
方案置信度来源可比性可阈值化

五、工业界踩坑实录

⚠️ 教训 1:Prompt 硬刚 JSON

用纯 Prompt 让 LLM 输出 {"intent": "..."} 在工业上是反模式。
正确做法:用原生 Function Calling 或 Structured Output。

⚠️ 教训 2:意图>50 类 Few-shot 退化

业界共识:
• <30 意图:LLM Zero-shot 够用
• 30~100:Few-shot + Embedding top-K
• 100+:必须先 Embedding 缩范围

⚠️ 教训 3:意图层不该独立于工具

现代 Agent 设计倾向于取消独立的意图分类层,把"意图判断"内嵌到"工具选择"中。
代表:OpenAI Assistants、智谱 Agents、LangGraph。

⚠️ 教训 4:规则要"宁漏勿误"

规则只识别高特异性词(医学术语、品牌、SKU)。
泛用动词/名词("记录"、"体重")不该单独触发意图。

八、综合结论

  1. 当前的"关键词 + 伪置信度"方案在工业上属于 2017 年前的范式,已被几乎所有头部公司淘汰。
  2. 2024~2025 工业 SOTA 是 Hybrid Routing,核心组件:Function Calling(主)+ Embedding 召回(辅)+ 规则白名单(fast-path)。
  3. PangHu 项目天然适配 LLM Function Calling,因为意图与工具一一对应,且基础设施齐备。
  4. 置信度问题的根本解法是采用余弦相似度或工具触发信号,而不是修补字符占比公式。
  5. 推荐演进路径:Step 1 开放 AgentLoop → Step 2 加 Embedding 召回 → Step 3 建立评估闭环。
