### 1.2 Agent Tool 与外部能力的边界

| 能力 | 归属 | 理由 |
| --- | --- | --- |
| 智能推荐 | Agent Tool（read） | 由用户对话/卡片触发，输出结构化结果给 LLM 与卡片 |
| 提交反馈 | Agent Tool（write） | 仍由对话/卡片触发，但需要写权限独立工具 |
| 陪玩历史查询 | Agent Tool（read） | LLM 可主动用于回答"我最近陪 Mimi 玩了什么"等问题 |
| 周报获取 | Agent Tool（read） | 用户提问时返回快照 |
| 周报生成 | Scheduler | 每周一凌晨预生成快照写入数据库 |
| 主动消息检测 | Scheduler | 离线、批处理，不能挂在用户请求上 |
| 主动消息呈现 | Agent + 前端 | 用户进入对话时拉取 pending，作为开场白 |
| PWA Push | **本期不做** | 国内 PWA Push 受限；以对话开场白替代 |

**结论**：架构主链路仍是 Agent Tool。Scheduler 和 ProactiveMessage 表是**新增旁路**，与 Agent Tool 通过数据库解耦，不改变现有 AgentLoop 的执行模型。

## 2. 数据模型

### 2.1 Cat 表扩展

新增字段（向后兼容，全部可空，老数据通过引导补全）：

```prisma
model Cat {
  id              String   @id @default(cuid())
  // ...原有字段（name, breed, gender, birthDate, weight, avatar, userId, isActive）

  // ===== 陪玩功能新增 =====
  personality     String?  // 'active' | 'curious' | 'clingy' | 'aloof'
  energyBaseline  Int?     // 1..5，静息精力档位
  healthTags      String?  // JSON 数组字符串，如 '["overweight","senior"]'
                           // 类型约定：dev(SQLite) 与 prod(PostgreSQL) 均使用 String，
                           // 不使用 PostgreSQL 原生数组，避免 dev/prod 查询逻辑分叉。
                           // service 层统一序列化/反序列化（JSON.parse / JSON.stringify）。
                           // 原因：healthTags 仅 4 枚举值、低基数、读多写少、不参与索引查询。
                           // 若未来需要按 tag 索引查询（如"查所有 senior 猫"），
                           // 再独立为 CatHealthTag 关系表。

  // ===== 关联 =====
  feedbacks       PlayFeedback[]
  playRecords     PlayRecord[]
  proactiveMessages ProactiveMessage[]
}
```

> 字段 `personality / energyBaseline / healthTags` 是**全功能共享**，后续健康检查、营养建议等工具都可使用，不仅服务陪玩。

### 4.2 主流程

```ts
async function recommend(input: RecommendInput, ctx: AgentContext): Promise<RecommendOutput> {
  const cat = await catProfileService.getById(input.catId)
  if (!cat || !cat.personality) {
    return needProfileCompletion(cat)   // 引导用户补全档案
  }

  const availableTime = input.availableTime ?? 10
  const currentEnergy = input.currentEnergy ?? cat.energyBaseline ?? 3
  const pref = await preferenceService.getByCatId(cat.id)  // P0 返回空，P1 返回真实数据

  // 健康过滤是绝对硬约束，永不放宽
  const healthyPool = applyHealthFilter(games, cat.healthTags)
  if (healthyPool.length === 0) {
    return emptyResultWithVetHint()  // L2 双层降级：连健康池都空
  }

  // soft-fallback 三步放宽，逐步尝试直到结果 ≥ 3 或全部用完
  const result = tryWithSoftFallback({
    pool: healthyPool,
    cat,
    availableTime,
    currentEnergy,
    pref,
    preferredCategory: input.preferredCategory,
  })

  if (result.length >= 1) {
    return { suggestions: result.slice(0, 5), fallback: false }
  }

  // L1 降级：忽略 currentEnergy/availableTime/preferredCategory，仅按性格 + 健康过滤
  const l1 = fallbackRecommend(cat, healthyPool)
  if (l1.suggestions.length > 0) return l1

  // L2 降级：L1 也空（理论上不会到这里，因为 healthyPool 非空，但保险）
  return emptyResultWithVetHint()
}

interface SoftFallbackOptions {
  pool: PlayGame[]
  cat: CatProfile
  availableTime: number
  currentEnergy: number
  pref: CatPreference
  preferredCategory?: GameCategory
}

function tryWithSoftFallback(opts: SoftFallbackOptions): ScoredItem[] {
  // 步骤 0：默认参数（maxPerCategory=2，preferredCategory 硬过滤，原 availableTime）
  // 步骤 1：maxPerCategory 提到 3
  // 步骤 2：preferredCategory 降级为软加权（+20 bonus）
  // 步骤 3：availableTime ±50%
  const steps: Array<() => ScoredItem[]> = [
    () => scoreAndDiversify(opts, { maxPerCategory: 2, categoryMode: 'hard', timeFlex: 1.0 }),
    () => scoreAndDiversify(opts, { maxPerCategory: 3, categoryMode: 'hard', timeFlex: 1.0 }),
    () => scoreAndDiversify(opts, { maxPerCategory: 3, categoryMode: 'soft', timeFlex: 1.0 }),
    () => scoreAndDiversify(opts, { maxPerCategory: 3, categoryMode: 'soft', timeFlex: 0.5 }),
  ]
  for (const step of steps) {
    const r = step()
    if (r.length >= 3) return r
  }
  return steps[steps.length - 1]()  // 全部放宽完仍不足，返回最后一步结果
}

interface ScoreOptions {
  maxPerCategory: number
  categoryMode: 'hard' | 'soft'   // hard=过滤；soft=+20 bonus 不过滤
  timeFlex: number                 // availableTime 的乘数（0.5 表示接受 ±50%）
}

function scoreAndDiversify(opts: SoftFallbackOptions, so: ScoreOptions): ScoredItem[] {
  let pool = opts.pool
  const categoryBonus = new Set<string>()
  if (opts.preferredCategory) {
    if (so.categoryMode === 'hard') {
      pool = pool.filter(g => g.category === opts.preferredCategory)
    } else {
      // 软加权：不删，但该类别游戏加 20 分 bonus（在打分后追加）
      pool.forEach(g => {
        if (g.category === opts.preferredCategory) categoryBonus.add(g.id)
      })
    }
  }

  const adjTime = opts.availableTime * so.timeFlex
  const scored = pool.map(g => {
    const sP = personalityScore(g, opts.cat.personality!)
    const sE = energyScore(g, opts.currentEnergy)
    const sT = timeScore(g, adjTime)
    const sR = preferenceScore(g, opts.pref)
    let total = sP * 0.35 + sE * 0.25 + sT * 0.20 + sR * 0.20
    if (categoryBonus.has(g.id)) total += 20
    return {
      game: g,
      score: Math.round(total),
      breakdown: { personality: sP, energy: sE, time: sT, preference: sR },
      reasons: buildReasons(g, opts.cat, { sP, sE, sT, sR }, opts.availableTime),
    }
  })

  scored.sort((a, b) => b.score - a.score)
  return diversify(scored, { maxPerCategory: so.maxPerCategory, top: 5 })
}
```

### 4.3 子分数算法

#### 4.3.1 PersonalityScore — 三档离散

```ts
// SUBCOMPATIBLE 仅兜底"未在 fitsPersonality 显式打标"的次匹配场景。
// aloof 在游戏库里已显式标注（feather-fishing / mouse-toy / catnip-toy
// 都标了 aloof），故 SUBCOMPATIBLE.aloof 留空数组，避免与显式标注重复计分。
const SUBCOMPATIBLE: Record<Personality, GameCategory[]> = {
  active:  ['hunting', 'chase'],
  curious: ['climbing', 'puzzle'],
  clingy:  ['interaction'],
  aloof:   [],
}

function personalityScore(game: PlayGame, personality: Personality): number {
  if (game.fitsPersonality.includes(personality)) return 100
  if (SUBCOMPATIBLE[personality].includes(game.category)) return 60
  return 0
}
```

#### 4.3.2 EnergyScore — 线性距离

```ts
function energyScore(game: PlayGame, currentEnergy: number): number {
  const diff = Math.abs(currentEnergy - game.energyCost)
  return Math.max(0, 100 - diff * 25)
}
```

| diff | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| score | 100 | 75 | 50 | 25 | 0 |

#### 4.3.3 TimeScore — 梯形函数

```ts
function timeScore(game: PlayGame, availableTime: number): number {
  if (availableTime <= 0) return 0
  const ratio = game.durationMin / availableTime
  if (ratio <= 1.0) return Math.round(60 + 40 * ratio)
  if (ratio <= 1.5) return Math.round(100 - 100 * (ratio - 1.0))
  return 0
}
```

| ratio | 0.5 | 0.8 | 1.0 | 1.2 | 1.5 | >1.5 |
| --- | --- | --- | --- | --- | --- | --- |
| score | 80 | 92 | 100 | 80 | 50 | 0 |

#### 4.3.4 PreferenceScore — 含冷启动

```ts
interface CatPreference {
  gameStats: Record<string, { count: number; avgScore: number }>
  categoryStats: Record<string, { count: number; avgScore: number }>
}

const NEUTRAL = 60
const MIN_GAME_SAMPLE = 2
const MIN_CAT_SAMPLE = 3

function preferenceScore(game: PlayGame, pref: CatPreference): number {
  const g = pref.gameStats[game.id]
  if (g && g.count >= MIN_GAME_SAMPLE) {
    return Math.round((g.avgScore - 1) * 25)   // 1→0, 5→100
  }
  const c = pref.categoryStats[game.category]
  if (c && c.count >= MIN_CAT_SAMPLE) {
    return Math.round((c.avgScore - 1) * 25 * 0.7)  // 类别级打 0.7 折
  }
  return NEUTRAL
}
```

**冷启动设计**：

- 无任何反馈数据时，所有游戏的 `PreferenceScore = 60`，该项贡献固定 12 分（60×0.2），不影响排序。
- 排序仍由 PersonalityScore + EnergyScore + TimeScore 主导。
- P1 偏好学习上线时此函数自动启用，**无需修改公式**。

### 4.4 健康过滤

> **单一数据源原则（v2.0 修正）**：所有禁忌**只在** `game.contraindications` 字段里。`ENERGY_BAN`、`TAG_FORBID_GAMES` 等批量规则**只存在于 seed 脚本**里，启动时展开写入每条游戏的 `contraindications`。运行时**只读一个字段**。

#### 4.4.1 seed 展开（一次性，启动时执行）

```ts
// backend/src/data/playGames.seed.ts
//
// 产品规则（与 PRD §4.4.5 对齐）：
//   senior   → 禁玩 energyCost ≥ 4 的所有游戏
//   post_op  → 禁玩 energyCost ≥ 3 的所有游戏
//   kitten   → 显式禁玩 catnip-toy + laser-chase
// 启动时根据这些规则把 contraindications 展开到每条游戏。

function expandContraindications(games: PlayGame[]): PlayGame[] {
  return games.map(g => {
    const tags: HealthTag[] = [...g.contraindications]
    if (g.energyCost >= 4) tags.push('senior')
    if (g.energyCost >= 3) tags.push('post_op')
    // kitten 由游戏自报（catnip-toy / laser-chase 已在数据里显式声明）
    return { ...g, contraindications: Array.from(new Set(tags)) }
  })
}
```

#### 4.4.2 运行时过滤

```ts
function applyHealthFilter(games: PlayGame[], healthTags: HealthTag[] = []): PlayGame[] {
  if (healthTags.length === 0) return games
  return games.filter(g => !g.contraindications.some(c => healthTags.includes(c)))
}
```

> overweight 不进过滤层。它的"鼓励运动"语义留给后续的 **加权调整**（P1+），本期暂不实现。
>
> 修改禁忌策略时**只改 seed 脚本或游戏数据**，运行时代码无需改动。

### 4.5 多样性约束

```ts
function diversify(
  scored: ScoredItem[],
  opts: { maxPerCategory: number; top: number },
): ScoredItem[] {
  const result: ScoredItem[] = []
  const count: Record<string, number> = {}
  for (const item of scored) {
    const c = item.game.category
    if ((count[c] ?? 0) >= opts.maxPerCategory) continue
    result.push(item)
    count[c] = (count[c] ?? 0) + 1
    if (result.length >= opts.top) break
  }
  return result
}
```

### 4.6 降级策略

```ts
// L1 降级：忽略 currentEnergy/availableTime/preferredCategory，仅按性格 + 健康过滤取 3 条
function fallbackRecommend(cat: CatProfile, healthyPool: PlayGame[]): RecommendOutput {
  const fits = healthyPool.filter(g => g.fitsPersonality.includes(cat.personality!))
  const picked = (fits.length > 0 ? fits : healthyPool).slice(0, 3)

  // reasons 用产品文案，禁止"降级""未匹配"等开发者术语，避免被 LLM 复述给用户
  const reasons = [`按${PERSONALITY_LABEL[cat.personality!]}偏好为你挑选`]

  return {
    success: true,
    fallback: true,
    suggestions: picked.map(g => ({
      game: g,
      score: 0,                // 前端在 fallback=true 时不展示 score
      breakdown: null,
      reasons,
    })),
  }
}

// L2 降级：健康池本身就空（所有游戏都被禁忌）
function emptyResultWithVetHint(): RecommendOutput {
  return {
    success: false,
    fallback: true,
    message: '当前健康标签下暂无合适游戏，建议咨询兽医',
    suggestions: [],
  }
}
```

> **降级文案规则**：`fallback: true` 时 reasons **必须**使用面向用户的产品文案。`fallback`/`success` 字段用于前端判断展示模式，**不进入 LLM 上下文**——LLM 看到的 reasons 与正常路径无差异，避免它复述"降级"等术语。

### 4.7 解释生成（reasons）

```ts
function buildReasons(
  game: PlayGame,
  cat: CatProfile,
  bd: { sP: number; sE: number; sT: number; sR: number },
  availableTime: number,
): string[] {
  const reasons: string[] = []
  if (bd.sP === 100) reasons.push(`匹配${PERSONALITY_LABEL[cat.personality!]}性格`)
  if (bd.sE === 100) reasons.push('精力档位完全匹配')
  else if (bd.sE >= 75) reasons.push('精力档位接近')
  if (bd.sT === 100) reasons.push(`刚好 ${availableTime} 分钟`)
  else if (bd.sT >= 80 && game.durationMin < availableTime) reasons.push('时间充裕')
  if (bd.sR >= 75) reasons.push(`${cat.name}之前很喜欢`)
  if (reasons.length === 0) reasons.push('综合评估推荐')
  return reasons
}
```

> reasons 由后端**确定性生成**，不调用 LLM。卡片直接展示。

### 5.2 SubmitPlayFeedbackTool（P0，write）

对齐 [allergyRecord.tool.ts](backend/src/agent/tools/allergyRecord.tool.ts) 的 write 工具范式：token 校验 + 归属校验 + 审计字段。

```ts
export const SubmitPlayFeedbackTool: Tool = {
  name: 'submit_play_feedback',
  description: '记录某次陪玩的评分。当用户表达对某游戏的喜好（如"Mimi 很喜欢羽毛"）时使用。需要用户确认后方可执行（写入操作）。',
  schema: z.object({
    catId: z.string(),
    gameId: z.string(),
    score: z.number().int().min(1).max(5),
    completion: z.boolean().optional(),
    actualDuration: z.number().optional(),
    playedAt: z.string().optional().describe('陪玩日期（ISO），留空则用当前时间'),
  }),
  permissions: ['write'],
  call: async (input, ctx: AgentContext) => {
    // 1. 确认令牌校验（双重保险，对齐 AllergyRecordTool）
    if (!ctx.confirmationToken?.verified) {
      return { success: false, message: '写入操作需用户确认后方可执行' }
    }

    // 2. 所有权校验 + 同步冗余 userId
    const cat = await prisma.cat.findFirst({
      where: { id: input.catId, userId: ctx.userId },
      select: { id: true, userId: true, name: true },
    })
    if (!cat) {
      return { success: false, message: '无权访问该猫咪信息' }
    }

    // 3. 写入（含审计字段）
    return playFeedbackService.upsert({
      ...input,
      userId: cat.userId,
      createdBy: ctx.userId,
      source: 'agent',
      confirmedAt: ctx.confirmationToken.confirmedAt,
      playedAt: input.playedAt ? new Date(input.playedAt) : new Date(),
    })
  },
}
```

> REST 通道（`POST /api/play/feedback`）走 JWT 鉴权中间件，校验 cat 归属后写入，`source='rest'`，`confirmedAt=null`。两条通道共享 `playFeedbackService.upsert`，仅审计字段不同。

### 5.6 REST API（与 Agent Tool 平行的通道）

陪玩功能存在两条并行通道，最终都调用同一 service 层：

| 通道 | 入口 | 适用场景 | 鉴权 |
| --- | --- | --- | --- |
| Agent Tool | LLM 决定调用 | 对话式交互（用户口述、问询） | AgentContext + confirmationToken（write） |
| REST | 前端直接调用 | 确定性 UI 操作（表单、列表、配置） | JWT 中间件 |

**REST 端点清单**（路由文件：`backend/src/routes/play.routes.ts`）：

| Path | Method | 阶段 | Request | Response | 参考 |
| --- | --- | --- | --- | --- | --- |
| `/api/play/feedback` | POST | P0 | `{ catId, gameId, score, completion?, actualDuration?, playedAt? }` | `{ success, recordId }` | §5.2 / §7.3 |
| `/api/play/history` | GET | P1 | `?catId=&days=7` | `{ records[], summary }` | §5.3 |
| `/api/play/weekly-report` | GET | P1 | `?catId=&week=YYYY-WW` | `{ summary, topGames[], categoryDistribution }` | §5.4 |
| `/api/proactive/pending` | GET | P2 | `?catId=` | `{ messages[] }` | §6.3 |
| `/api/proactive/:id/shown` | POST | P2 | path: `id` | `{ success }` | §6.3 |
| `/api/proactive/setting` | PUT | P2 | `{ enabled: boolean }` | `{ success }` | §6.4 |

**统一约定**：

- 所有端点都走 JWT 鉴权中间件，从 token 解析 `userId`
- 涉及 `catId` 的端点，**必须**校验 `cat.userId === req.userId`，与 Agent Tool 通道保持一致
- 写入端点（POST/PUT）冗余写入 `userId`，便于后续聚合查询
- 错误码：`401` 未鉴权 / `403` 无权访问该猫咪 / `404` 资源不存在 / `429` 限频

> REST 通道不替代 Agent Tool。Agent Tool 用于 LLM 主导的对话场景（如"帮我记一下 Mimi 刚才玩羽毛鱼很喜欢，5 颗星"），REST 用于 UI 主导的确定性操作（表单提交、列表查询、配置开关）。两者最终写入同一张表。

## 6. 主动服务（P2）

### 6.1 调度器

```ts
// backend/src/schedulers/proactiveScanner.ts
//
// 每日凌晨执行：
// 1) 扫描所有 active 猫咪
// 2) 对每只猫执行三项检测
// 3) 命中则向 ProactiveMessage 表写入 pending 消息
// 4) 同类型 24h 内已存在 pending/shown 则跳过（去重）

cron.schedule('0 3 * * *', async () => {
  const cats = await prisma.cat.findMany({ where: { isActive: true }})
  for (const cat of cats) {
    await detectSilent(cat)
    await detectLowActivity(cat)
    await detectPreferenceDiscovery(cat)
  }
})
```

### 6.2 三项检测

| 类型 | 触发条件 | payload 内容 |
| --- | --- | --- |
| silent | 同猫咪 ≥ 48h 无 PlayRecord | `{ days: 2, suggestedGameId }` |
| low_activity | 本周 PlayRecord 总时长较上周下降 ≥ 40% | `{ ratio, suggestedCategory }` |
| discovery | 同类别评分 ≥ 4 累计达到 5 次（首次达成） | `{ category, topGameIds: [...] }` |

> "首次达成"通过查询是否已存在同 catId+type+category 的 ProactiveMessage 实现。

### 6.3 呈现机制

前端进入 AI 对话页时：

```ts
// 前端 onMounted
const pending = await api.get(`/api/proactive/pending?catId=${catId}`)
if (pending.length > 0) {
  showProactiveBanner(pending[0])  // 渲染开场白卡片
  await api.post(`/api/proactive/${pending[0].id}/shown`)
}
```

主动消息**不与 Agent Tool 路径耦合**。它是独立的小型 REST 通道，单一职责：拉 pending、标记 shown。

### 6.4 用户开关

档案页提供"接收主动提醒"开关，关闭后跳过该用户的所有检测。

## 10. 与既有 Agent Framework 的衔接

### 10.1 LLM_TOOL_CALLING_LOOP 兼容

陪玩工具完全符合 [AgentLoop](backend/src/agent/AgentLoop.ts) 的 ReAct 调用约定：

- `schema` 用 zod，由 AgentLoop 解析为 OpenAI Function 描述
- `permissions` 由 AgentExecutor 校验（write 工具走二次确认通道）
- `call` 返回的对象直接进入 `AgentReporter`，由 cardRegistry 路由到对应组件

无需改动 AgentLoop。

### 10.2 工具描述对 LLM 的关键约束

工具 `description` 字段遵循现有惯例（中文 + 触发场景），由 LLM 决定何时调用。**不需要在 system prompt 里再加规则**。

### 10.3 缺失字段的对话补齐

如果用户提问时未指定 catId 且家中多猫，工具返回 `needCatSelection`，由 AgentLoop 把信息回填给 LLM 让其向用户提问。这与现有 CatInfoTool 的处理方式一致。
