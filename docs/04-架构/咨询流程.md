# 喵喵医生 - 问诊交互流程文档

## 概述

本文档描述了"喵喵医生"的完整问诊交互流程，包括前端UI交互、后端API处理和对话状态管理。

## 核心设计原则

1. **信息优先收集**：在给出建议前，先收集关键症状信息
2. **结构化问诊**：使用 `<ask>` 标记触发问诊卡片交互
3. **上下文积累**：问诊收集的信息会影响最终建议
4. **紧急情况识别**：明确的紧急症状直接建议就医，不问诊

## 交互流程

### 正常问诊流程

```
用户输入症状
    ↓
AI 判断信息是否完整
    ↓
    ├─ 信息完整 → 直接给出建议
    │
    └─ 信息不足 → 返回 <ask>问题</ask>
           ↓
       前端渲染问诊卡片
           ↓
       用户点击快捷选项或自定义输入
           ↓
       前端发送答案到后端
           ↓
       后端更新对话上下文 (collectedInfo)
           ↓
       AI 基于完整信息给出建议
```

### 紧急情况流程

```
用户描述明确紧急症状
    ↓
AI 识别为紧急（包含时间信息）
    ↓
返回紧急建议 + isEmergency=true
    ↓
前端以红色紧急卡片渲染
```

## 数据结构

### ConversationContext（对话上下文）

```typescript
interface ConversationContext {
  catProfileId: string          // 猫咪档案ID
  symptoms: string[]            // 症状列表
  duration?: string             // 持续时间（已收集）
  frequency?: string            // 频率（已收集）
  severity?: string             // 严重程度（已收集）
  otherInfo: string[]           // 其他信息
  turnCount: number             // 对话轮次
  isAsking: boolean             // 当前是否在问诊
  currentQuestion?: string      // 当前问诊问题
  collectedInfo: Record<string, string>  // 已收集的信息键值对
}
```

### ChatMessage（聊天消息）

```typescript
interface ChatMessage {
  id: string
  role: 'user' | 'assistant' | 'system'
  content: string
  timestamp: Date
  isEmergency?: boolean         // 是否为紧急情况
  citations?: Citation[]        // 知识来源引用
  askQuestion?: {               // 问诊问题（如果有）
    question: string
    options?: string[]          // 可选的快捷回答选项
    collectedKey?: string       // 此问题收集的信息键名
  }
  collectedInfo?: Record<string, string>  // 当前轮次已收集的信息
}
```

## 后端 API

### POST /api/chat

**请求体：**
```json
{
  "message": "我的猫不吃东西",
  "conversationContext": {
    "catProfileId": "1",
    "turnCount": 0,
    "isAsking": false,
    "collectedInfo": {}
  },
  "catProfile": {
    "id": "1",
    "name": "小橘",
    "ageMonths": 24,
    ...
  }
}
```

**响应（问诊）：**
```json
{
  "content": "",
  "isEmergency": false,
  "askQuestion": "这种情况持续多久了？",
  "collectedKey": "duration",
  "conversationContext": {
    "catProfileId": "1",
    "turnCount": 1,
    "isAsking": true,
    "currentQuestion": "这种情况持续多久了？",
    "collectedInfo": {}
  }
}
```

**响应（建议）：**
```json
{
  "content": "**请立即就医！**持续呕吐腹泻超过24小时...",
  "isEmergency": true,
  "citations": [
    { "title": "健康医疗指南", "similarity": 0.92 }
  ],
  "conversationContext": {
    "catProfileId": "1",
    "turnCount": 2,
    "isAsking": false,
    "collectedInfo": {
      "duration": "3天了"
    }
  }
}
```

## 前端组件

### AskInteractionCard

问诊交互卡片组件，根据问题类型提供：
- **快捷选项按钮**：针对常见问题的预设答案
- **自定义输入框**：允许用户输入其他答案
- **提交动画**：点击后自动触发下一轮对话

快捷选项映射：
| 问题关键词 | 快捷选项 |
|-----------|---------|
| 多久/持续/时间 | 不到1天, 1-2天, 3-7天, 超过7天 |
| 几次/频率 | 1次, 2-3次, 4-5次, 多次/一直 |
| 精神/状态 | 精神很好, 稍微差一点, 明显萎靡, 非常差 |

### MessageBubble

消息气泡组件，根据消息类型渲染：
- **用户消息**：橙色渐变气泡，右对齐
- **普通助手消息**：灰色气泡，左对齐
- **紧急消息**：红色边框 + 紧急图标 + 脉冲动画
- **问诊消息**：白色卡片 + 蓝色头部 + 问诊交互区

## 问诊问题到信息键的映射

| 问题关键词 | 信息键 | 用途 |
|-----------|--------|------|
| 多久、持续 | duration | 症状持续时间 |
| 几次、频率 | frequency | 症状发作频率 |
| 精神、状态、严重 | severity | 精神状态/严重程度 |
| 其他、还有什么 | other | 其他补充信息 |

## 系统提示词要点

```markdown
## ⚠️ 核心原则：按顺序判断，匹配即停止

### 步骤1：判断信息是否完整
**如果用户未说明症状持续时间，必须追问！**

问诊触发词（出现这些词但无时间说明时）：
- 不吃东西 / 不吃饭 / 不吃
- 不喝水 / 没喝水
- 没精神 / 精神差 / 萎靡
- 呕吐 / 拉稀 / 腹泻
- 咳嗽 / 喘气 / 呼吸困难

问诊格式：
<ask>单个问题</ask>

**严禁：在追问时给诊断、建议或判断是否紧急**

### 步骤2：判断是否紧急（仅在步骤1确认信息完整后）
用户明确说了以下【已持续】的症状：
- "呼吸困难" + 持续进行中
- "无法排尿" / 憋尿
- "呕吐/腹泻" + "超过24小时" / "一天多" / "两天了"
- "不食/不吃" + "超过24小时" / "一天多" / "两天了"
- 出血 / 骨折 / 抽搐 / 昏迷

→ 第一句必须是"**请立即就医！**"

### 步骤3：正常回答
症状清晰、信息完整、非紧急情况

→ 基于知识库片段回答
→ 片段不足时说："我的知识库暂时没有这方面的记录，建议咨询专业兽医"
```

## 视觉设计

### 色彩系统

| 用途 | 颜色 | CSS |
|------|------|-----|
| 主色 | 橙色渐变 | `from-orange-400 to-amber-500` |
| 问诊 | 蓝色系 | `bg-blue-50 border-blue-200` |
| 紧急 | 红色系 | `bg-red-50 border-red-200` |
| 用户消息 | 橙色渐变 | `from-orange-400 to-amber-500` |
| 助手消息 | 灰色 | `bg-gray-100` |

### 动画效果

- **问诊图标**：左右摆动 (`animate: rotate[0, 10, -10, 0]`)
- **紧急图标**：脉冲缩放 (`animate: scale[1, 1.2, 1]`)
- **消息进入**：从下向上淡入 (`y: 20 → 0, opacity: 0 → 1`)
- **输入指示**：三个弹跳点 (`animate-bounce` with delays)

## 测试场景

### 场景1：普通问诊流程
1. 用户："我的猫不吃东西"
2. AI：<ask>这种情况持续多久了？</ask>
3. 用户点击"3-7天"
4. AI：根据症状持续时间给出建议

### 场景2：紧急情况
1. 用户："我的猫持续呕吐超过24小时"
2. AI：**请立即就医！** 持续呕吐腹泻超过24小时属于紧急情况...

### 场景3：信息完整
1. 用户："幼猫每天应该吃几顿"
2. AI：直接回答，不问诊
