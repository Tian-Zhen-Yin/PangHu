猫咪陪玩 × AI 聊天
交互合一探索

当前「陪玩推荐」是独立页面，「喵喵医生」是对话页面 —— 二者本可共生。本文给出评审意见、3 套合一方案（含打分）与可点击原型。

1

现状评审意见

基于现有代码与 PRD

🔍 核心发现：能力已存在，入口被割裂

后端 Agent 已注册 RECOMMEND_play 工具，对话里「陪 Mimi 玩什么」本可直接触发推荐；但前端 cardRegistry.ts 并未为它注册卡片，于是推荐被迫塞进独立的 /play 页面。结果是同一份能力出现两套 UI、两套埋点 source、两条用户心智路径，这正是「交互可优化」的根源。

高

双入口割裂，用户心智分裂

陪玩在 Tab/独立页，问健康在聊天页。用户想「边问边玩」时要来回跳转，且陪玩页的猫咪切换与聊天页的 CatSelector 是两套状态，容易不同步。
高

陪玩卡片无法进入对话上下文

PRD §6.1 主流程本就是「对话式推荐为主入口」，但实现里对话拿不到陪玩卡片（缺 card 注册），导致 PRD 设计意图与落地脱节，反馈闭环 recommendation→feedback 被拆在两处。
中

场景预设与建议芯片重复造轮子

陪玩页有「只有5分钟/精力旺盛」等 chips（ScenarioPresets），聊天页有 contextualSuggestions chips，两者形态几乎一致却各写一份，维护成本翻倍。
中

反馈打分埋点 source 不统一

陪玩卡片埋点 source 写死 'page'，而 PRD §7 期望区分 chat/quick/scenario。合一后可用统一 source 维度，漏斗更干净。
低

视觉语言已统一，迁移成本低

两处都已用奶油色系 + MascotCharacter + 同一套 design token，合并不会有视觉断层，主要工作量在交互编排而非重做样式。

A

方案 A · 对话原生陪玩卡片

★ 推荐方案

聊天即陪玩 —— 把推荐卡片织进对话流

取消独立陪玩页，用户在喵喵医生对话里直接说「陪 Mimi 玩什么」，Agent 调用 RECOMMEND_play 工具，推荐卡片作为一种气泡内联渲染，打分、记录都在对话里完成。场景预设变成输入框上方的快捷 chips。

90
加权总分
优点
  • 完全对齐 PRD「对话式推荐为主入口」原意
  • 复用现有 AgentCardRenderer + cardRegistry，只需补一个 PlaySuggestionCard 注册
  • 反馈闭环零跳转：推荐→打分→学习全在一条对话线
  • 多猫切换、上下文、历史会话天然复用聊天页能力
需注意
  • 纯对话对新手「我能玩陪玩」的可发现性稍弱，需靠 chips + 首页卡片引导
  • 卡片在窄气泡内信息密度要克制，详情走展开

B

方案 B · 模式切换 + 陪玩抽屉

兼顾可发现性

一个壳两种模式 —— 顶部切「问诊 / 陪玩」

保留单一对话壳，顶部分段控件在「问诊」与「陪玩」间切换。切到陪玩时，输入框上方升起一个轻量配置抽屉（时长/精力/类别），结果仍以卡片形式落在同一对话流，打分内联。既有显式入口，又共享对话上下文。

81
加权总分
优点
  • 显式「陪玩」入口，新手可发现性强
  • 配置抽屉比纯自然语言更精确（明确选时长/精力）
  • 仍共享对话流与多猫状态，避免双页
需注意
  • 模式切换增加一层状态，需处理两模式的 prompt/工具集差异
  • 抽屉 + 对话两种交互并存，认知负担略高于 A

C

方案 C · 双 Tab 同壳（最低成本）

最快落地

共用一个页面外壳，顶部 Tab 切两个面板

把陪玩页与聊天页合进同一路由 /assistant，顶部两个 Tab：「对话」「陪玩」。共享 CatSelector、头部、底部输入。两面板各自保留现有 UI，只是被装进同一外壳，状态（当前猫）打通。改动最小，但两个面板仍是各自独立的体验。

74
加权总分
优点
  • 工程量最小，几乎是把两页塞进一个 Tab 容器
  • 两个入口都极其显眼，零学习成本
  • 共享猫咪选择器，解决状态不同步问题
需注意

  • 反馈闭环仍隔在陪玩面板内，未流入对话
  • 长期看是过渡形态，非终态

3

结论与建议

推荐 方案 A（对话原生卡片）为终态，方案 C 可作为一周内的过渡。

方案 A 最贴合 PRD「对话式推荐为主入口」的原始设计，且复用现有 AgentCardRenderer 体系，落地只需：① 在 cardRegistry.ts 注册 RECOMMEND_play → PlaySuggestionCard；② 让 PlaySuggestionCard 适配卡片 toolOutput 契约；③ 把 ScenarioPresets 提升为输入框上方的快捷 chips。若团队希望同时照顾新手可发现性，可在方案 A 基础上叠加方案 B 的「陪玩」快捷入口（首页「今日陪玩」卡片点进来预填一句 prompt），即得到「A 为主、B 引导」的组合形态。
